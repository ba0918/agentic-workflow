# 品質検査ツール

## 目的

品質検査ツールは、ソースコードと仕様書にある機械判定可能な違反を検出します。特定のAIエージェントに依存せず、同じ検査を手動実行、Gitのコミット前処理、継続的インテグレーションから利用できなければなりません。

ここでいう品質検査には、Pythonコードの構造検査と型検査、日本語仕様書の文章検査を含みます。

## 配置

共通実装は `tools/quality` に配置します。このディレクトリには、検査をまとめて実行するコマンド、個別検査、設定、追加規則、テストを置きます。

Codex固有の終了処理は `tools/quality/agents/codex_stop.py` に配置します。この処理は共通検査の結果をCodexの終了時フックが要求するJSONへ変換するだけにします。

`.codex` には、Codexが読み込む `hooks.json` だけを置きます。品質検査の実装、設定、テストは置きません。

## 依存方向

Codex用の変換処理は共通品質検査に依存できます。共通品質検査は、Codex用の変換処理、Codexの設定、Codex固有の入力形式に依存してはいけません。

LefthookはGitのコミット前にコマンドを実行するツールです。Lefthookと継続的インテグレーションは、Codex用の変換処理を経由せず、共通品質検査を直接呼びます。

## 共通コマンドの契約

共通コマンドは、検査対象の範囲として作業ツリーまたはGitのステージ済み内容を受け取ります。違反がなければ終了コード0を返します。違反があれば非0を返し、原因を診断として出力します。

共通コマンドは、起動時のカレントディレクトリや暗黙の `PYTHONPATH` に依存してはいけません。リポジトリ直下以外から起動した場合も、同じ対象を検査して同じ結果を返します。

## 実行経路

次の実行経路は、同じ検査設定を使います。

- 共通コマンドを直接実行する経路
- Codexの終了時フックから変換処理を経由する経路
- Lefthookのコミット前処理から共通コマンドを呼ぶ経路

入口ごとに異なるのは、検査範囲と結果の表現だけです。Pylint、mypy、textlintの規則と検査対象は入口によって変えてはいけません。

## 移行条件

移行後は `.codex/quality` を残しません。既存のPython構造規則、型検査、仕様書の文章規則、部分ステージングの保護、非通常ファイルの拒否を維持します。
