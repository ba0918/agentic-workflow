# Plan lifecycle

Revise an unfinished plan at the same path. A new approval commit becomes its version. If the
revision changes product meaning, prohibitions, allowed differences, or human boundaries, return to
brainstorm first.

Files currently under `docs/plans/` are the unfinished-plan list. Remove a completed and merged
plan from the working tree; Git history preserves it. Do not maintain a second index or status
file.

Several unrelated plans may coexist. If a proposed plan overlaps an existing one, show the overlap
and let the human decide between revising it and creating a separate plan before leaving duplicate
candidates.
