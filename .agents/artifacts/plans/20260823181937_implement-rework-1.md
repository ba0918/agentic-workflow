plan から implement への受け渡しの約束を定める。

## この手順書の言葉

- **手順書**: plan が作り implement が実行する Markdown ファイル。この文書自身も手順書。
- **指紋**: ファイル内容の SHA-256。`sha256:` で始まる文字列。
- **実行**: implement を 1 回起動して手順書を進める単位。実行 ID（時刻と乱数）で識別する。
  旧 cycle のコードでは `attempt` と呼んでいる。
- **証拠**: 実行ごとに `.agents/artifacts/executions/<手順書 ID>/<実行 ID>/` に残すファイル群。
  最初に書く `binding.json` と、番号順の出来事ファイル。
- **「使用中」の印（claim）**: 旧 cycle が `.agents/runtime/cycles/current.claim` に置いていた、
  リポジトリ全体に 1 つのファイル。この手順書で廃止する。
- **残っている作業**: 同じ手順書に対する、終わっていない前の実行。

## 目的

旧 cycle は、起動時にリポジトリ全体へ「使用中」の印を置き、止まったあとに印を外す役が
無かったため、一度止まると誰も再開も片付けもできなかった。また手順書を自前で解析して
いたため、plan が作る手順書の書式と食い違った。改訂した `docs/spec/implement.md` は、
印を廃止し、証拠を起点に残っている作業を見つけて人が続けるか選ぶ流れと、手順書の読み取りを
plan 側のスクリプトに一本化することを定めた。この手順書はその前半を実装する。

改修は 2 つの手順書に分ける。この手順書（1/2）は、skill の改名、手順書の読み取りの一本化、
印の廃止と証拠からの復元、残っている作業の検出と再開を扱う。テストで示せない手順
（`artifact` / `external`）の証拠と `approval` は次の手順書（2/2）で扱う。1 回の実装で
終えられる大きさに収めるための分割で、1/2 が終わった時点でも implement は `test` の手順だけ
なら旧 cycle と同じように動く。

## 利用者が得る結果

止まった implement の実行が残っていても、次に同じ手順書で起動したとき、残っている内容
（どこまで進んだか、ブランチと作業ディレクトリの状態）を見て、「そのブランチで続ける」か

plan が作った手順書を、implement が同じ読み取りで受け付ける。
