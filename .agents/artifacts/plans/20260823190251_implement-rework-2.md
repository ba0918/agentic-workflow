## この手順書の言葉

- **手順書 / 指紋 / 実行 / 証拠**: 1/2 の手順書（`20260823181937`）と同じ意味。
- **完了の示し方**: 手順書の各手順が `**Completion:**` で宣言する 3 種類。`test`（先に失敗する
  テストを書いて通す）、`artifact`（作った物で示す。ファイルが決めた内容で存在し、形式検査を
  通り、人が読んで OK と言う）、`external`（外で確かめる。人が結果を見て OK と言う）。
- **成果物の確認（approval）**: `artifact` / `external` の手順で、人が成果物や結果を見て
  OK / NG を言うこと。手順書の `Human gates` の宣言とは別物で、宣言が無くても implement が
  必ず求める。記録は `approval` の出来事。

## 目的

1/2 を終えた implement は、手順書の読み取りと残っている作業の扱いが仕様どおりになったが、
手順の進め方は `test` だけで、`artifact` / `external` の手順に出会うと止まる。仕様書や skill
本文のように「テストで振る舞いを示せない」成果物を作る手順書は、これでは完了できない
（Phase 3.5 のきっかけになった問題の 2 つ目）。この手順書で、3 種類すべての手順を進め、
種類ごとの証拠で全手順完了を判定できるようにする。

## 利用者が得る結果

文章だけの手順書（`test` の手順が 1 つも無い手順書）でも、implement が手順ごとに証拠
（作ったファイルの指紋、形式検査の結果、人の確認）を残して、全手順完了に到達できる。
`test` の手順は 1/2 までと同じに動く。

## 何を変えて、何を変えないか

変えるもの:

- 出来事の種類に `artifact`、`external`、`approval` を足す
- `artifact` の手順: 作ったファイルの一覧と指紋、走らせた形式検査のコマンドと終了コードを
  記録する補助コマンド（`record-artifact`）
- `external` の手順: 何を確かめたか（手順書の記述の参照）と結果の短い要約を記録する補助コマンド
  （`record-external`）
- 成果物の確認を記録する補助コマンド（`approve`）。`rejected` なら止まる
- 各手順の完了の示し方と、記録しようとする証拠の種類が食い違ったら止まる（`test` の手順に
  `artifact` を記録しようとした、など）
- コミット前の検査（`stage`）と全手順完了の判定（`implementation-green`）を、種類ごとの証拠の
  並びで行う: `test` は `red` → `green` → `refactor` → `commit`、`artifact` は `artifact` →
  `approval` → `commit`、`external` は `external` → `approval` →（記録する物があれば）`commit`
- skill 本文に `references/artifacts.md` を足し、`SKILL.md`、`execution.md`、`evidence.md` を
  3 種類に合わせる

変えないもの:

- `test` の手順の進め方、テストの凍結、残っている作業の検出と再開、証拠の置き場所
- 手順書の読み取り（`plan_artifact.py`）、plan skill、brainstorm skill
- 手順書に宣言された `Human gates` の扱い（`human_gate` の出来事。成果物の確認とは別に、
  これまでどおり宣言があれば要求する）

## 外部への影響と、主なリスク

- 外部サービスとの入出力は無い
- `external` の手順で implement が実行できない確認（実機、人の操作）は、人に依頼して結果を
  聞く。implement が記録するのは要約と人の判断だけで、全出力や外部のログは残さない
- 形式検査のコマンドは手順書に書かれたものだけを走らせる。書かれていなければ検査無しとして
  記録する（検査を implement が勝手に選ばない）
- `approval` が `rejected` のとき、手順は止まる。直して再度 `artifact` / `external` を記録し、
  もう一度確認を求める流れは、1/2 の「続ける」（`resume`）で戻ってくる

## 失敗したらどこで止まるか

- テストで示す手順で、失敗するテストが書けないなら、その手順が既存の振る舞いを確かめようと
  している。テストを直す
- 手順書に無い振る舞いを決めたくなったら止まり、brainstorm に戻す
- 手順 7 で失敗が見つかったら、どの手順の範囲かを特定して戻る。特定できなければ人に伝える
